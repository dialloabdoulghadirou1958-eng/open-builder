# Open Builder 项目审计与功能路线图

更新时间：2026-06-15

## 1. 当前项目能力概览

Open Builder 当前已经不是一个简单的聊天界面，而是一个浏览器/桌面端均可运行的 AI Web 应用生成器。核心架构由以下模块构成：

- AI 生成循环：`src/lib/ai/generator.ts` 负责流式生成、工具调用、重试、终止、Plan Mode、子代理调度和技能上下文限制。
- 代码沙箱：`src/components/CodeViewer.tsx` 使用 Sandpack 提供实时预览、代码编辑、控制台查看、设备尺寸切换和 ZIP 下载。
- 文件工具：`src/lib/tools/fs-tools.ts` 支持项目初始化、读写、补丁、搜索、重命名、移动、依赖管理和环境变量管理。
- 会话系统：`src/store/conversation.ts` 与 `src/components/chat/SessionList.tsx` 支持多会话、搜索、置顶、归档、复制、删除和智能命名。
- 历史快照：`src/store/snapshot.ts` 使用 patch chain + checkpoint 存储项目历史，可在消息层查看 diff 与回滚。
- 项目模板：`src/store/project-templates.ts` 与 `src/components/chat/ProjectTemplateDialog.tsx` 支持把当前项目保存为本地模板，并从模板新建会话项目。
- 风格资产：`src/store/style-assets.ts` 与 `src/components/settings/tabs/StyleAssetsPanel.tsx` 支持保存品牌/风格资产，并将启用资产注入生成器上下文。
- 设置与凭据：`src/store/settings/*` 和 `src/store/secrets.ts` 支持模型、搜索、素材、主题、语言、Plan Mode、反向代理和加密凭据金库。
- 外部能力：支持 Tavily、Firecrawl、Jina Reader、Pixabay、Unsplash、NPM 搜索、Mohua 服务端代理、SSO、技能导入、技能目录、技能脚本和子代理。
- 多端包装：`src-tauri/` 已具备 Tauri 2 桌面与移动端构建配置。

## 2. 可以进一步完善的现有功能

### 2.1 生成可靠性

- 增加生成前/生成后的自动检查链路：依赖变更后自动读取 Sandpack 控制台、识别错误、触发修复提示。
- 将当前纯文本错误消息升级为结构化错误：区分网络错误、鉴权错误、模型错误、工具参数错误、上下文过长和运行时错误。
- 为 `retry` 和 `continue` 增加更明确的状态恢复策略，避免半完成 tool call、残留临时消息或重复快照影响后续生成。
- 对附件输入增加大小、类型、解析状态提示；PDF 目前以 data URL 进入上下文，后续应做真实文本抽取或明确提示不可解析。

### 2.2 会话与历史管理

- 会话列表已有搜索、置顶、归档和智能命名，但还缺少批量操作、筛选视图、导出/导入和数据占用统计。
- 快照能力已经成熟，但只在消息层暴露 diff/rollback；可以增加快照历史面板、命名快照、保留策略、按文件查看历史。
- `clear`、`fork`、`delete` 等高影响操作可增加更清晰的确认/撤销体验，降低误删风险。

### 2.3 代码编辑与预览体验

- 文件资源管理器已有搜索、新建、重命名、拖拽移动、下载，但可以补充冲突提示、非法路径校验、空文件夹展示和批量下载。
- 预览工具栏可扩展为“运行检查”入口，统一展示 Sandpack 控制台错误、依赖状态、构建状态和修复建议。
- 代码视图可以增加文件变更标记、未保存状态、格式化、查找替换和最近文件列表。

### 2.4 设置、凭据与安全边界

- API Key 与登录 token 已迁移到加密 vault，这是重要安全基础；后续可展示 vault 健康状态、迁移结果和最近一次解锁时间。
- Tauri 反向代理拥有全局 fetch/XHR 拦截能力，建议增加域名 allowlist、请求审计日志和一次性授权提示。
- 技能脚本明确不是强沙箱，当前已有警告；后续可增加可信来源标记、脚本执行前参数预览、执行日志和禁用本地 shell 的安全模式。
- 外部 URL 读取、图片代理、第三方搜索应统一做超时、并发限制、结果截断和来源展示。

### 2.5 文档与开发质量

- 本次审计发现 README 曾与实现存在偏差，例如核心文件路径、凭据存储说明、Plan Mode、技能系统、凭据金库和子代理等能力描述不完整；阶段一已先行校准，后续需要保持文档与实现同步。
- 当前只有 `pnpm lint`（`tsc --noEmit`），缺少单元测试、组件测试和端到端 smoke test。
- 可以增加架构文档、工具协议文档、技能开发指南和数据迁移说明，方便后续贡献。

## 3. 可以拓展的新功能方向

### 3.1 项目级工作流

- 项目健康检查：一键检查文件结构、依赖、环境变量、控制台错误、可访问性和响应式布局。
- 生成任务看板：把一次生成拆成计划、文件变更、依赖安装、运行检查、修复回合等阶段。
- 自动 QA 回合：生成完成后自动让 AI 读取控制台、检查关键文件、修复明显错误，再交付给用户。
- 项目模板库：用户可以保存自己的模板、首选依赖、设计系统和默认文件结构；基础本地模板库已完成，后续可继续扩展为品牌/风格资产库。

### 3.2 协作与版本能力

- 会话/项目导出包：导出代码、消息、快照、设置摘要和生成日志，便于迁移或审计。
- 本地 Git 集成：初始化仓库、生成提交、查看 diff、回滚到 commit、导出 patch；基础 patch 导出已完成，后续可接入桌面端 Git 命令。
- 云端同步：可选同步会话、快照、技能和项目资产，支持多设备继续工作。
- 分享链接：只读分享预览、代码包或生成过程。

### 3.3 生成质量增强

- 设计风格资产库：将 `apply_design_style` 扩展为可管理的风格包、品牌包、组件规范；基础本地风格资产库已完成。
- 多模型协作：规划模型、编码模型、审查模型分工；对高风险修改自动调用审查子代理。
- 需求澄清模板：把常见应用类型的需求澄清沉淀成可复用问卷。
- 自动文档生成：为生成项目输出 README、组件说明、部署指南和环境变量说明。

### 3.4 平台与生态

- 技能市场：展示技能来源、权限、脚本数量、最近更新和本地风险等级；基础本地目录增强已完成，后续可接入远程评分/来源信誉。
- 组件安装器增强：支持更多 registry、私有组件库、版本选择和安装回滚。
- 移动端体验强化：移动端完整文件查看、预览调试、会话管理和系统分享入口。
- 离线模式：内置本地模型/Ollama 引导、离线模板、离线技能和本地文档检索。

## 4. 阶段性开发计划

### 阶段一：审计结果固化与文档校准

目标：让当前项目能力、问题和路线图有一个可信的仓库内记录。

- 新增本文件，回答“哪些功能可完善、哪些功能可拓展”。
- 更新 README 中过时路径和遗漏功能。
- 验证 TypeScript 类型检查通过。

验收标准：

- `pnpm lint` 通过。
- README 与当前核心模块路径一致。
- 后续开发计划可直接作为 issue/里程碑拆分依据。

### 阶段二：测试与质量基线

目标：先保护纯逻辑模块，降低后续功能开发回归风险。

阶段进展：

- 已引入 Vitest，并新增 `pnpm test`。
- 已为 `fs-tools` / `env-tools`、`file-refs`、`settings` 迁移、`snapshot` 重放、`compress-context`、`merge-messages` 添加首批单元测试。
- 已新增 `.github/workflows/ci.yml`，在 PR、main 分支 push 与手动触发时执行 lint、test、build。
- 已通过 `pnpm lint`、`pnpm test`、`pnpm build` 验证。

后续工作：

- 继续为生成错误恢复、会话导出/导入、快照历史 UI 添加测试。
- 针对生产构建的超大 chunk 警告制定代码拆分方案。

验收标准：

- 核心纯逻辑测试覆盖主要边界条件。
- CI 能执行 lint、test、build。

### 阶段三：会话与历史体验产品化

目标：把已有会话/快照能力从“可用”提升到“好管理”。

阶段进展：

- 已增加会话导出/导入，导出包包含会话、项目文件、消息与快照。
- 已增加会话筛选：全部、置顶、归档、含项目、含错误。
- 已增加快照历史面板，支持命名、查看变更、恢复和删除；删除中间快照时会重建后续 patch 链。
- 已通过 `pnpm lint`、`pnpm test`、`pnpm build` 与本地浏览器渲染检查。

后续工作：

- 增加存储占用统计与清理入口。
- 为会话导入/导出 UI、快照历史交互补组件级或端到端测试。

验收标准：

- 用户可以备份并恢复一个完整会话项目。
- 用户可以不依赖消息列表找到历史快照。

### 阶段四：安全与权限治理

目标：降低高权限功能的误用风险。

阶段进展：

- 已为 Tauri 反向代理增加 host allowlist 与最近请求日志。日志只记录方法、类型、host 和 path，不记录 headers/body/query。
- 已为技能脚本执行增加持久化审计记录，系统设置中可查看最近执行并清空。
- 已将 API Key 设置提示修正为本地加密凭据金库。
- 已通过 `pnpm lint`、`pnpm test`、`pnpm build` 与本地设置页渲染检查。

后续工作：

- 为技能脚本执行增加执行前参数预览与更细粒度确认。
- 对外部 URL 读取、图片搜索、NPM 搜索统一增加超时、并发和结果大小限制。
- 在设置中继续整合 SSO、代理、技能脚本、vault 的安全状态总览。

验收标准：

- 高权限能力都有可见的开关、说明和最近行为记录。
- 默认配置保持保守，不影响浏览器普通使用。

### 阶段五：启动性能与包体优化

目标：降低首屏加载压力，让重型生成、预览和编辑能力按需进入。

阶段进展：

- 已将 `CodeViewer`、移动预览、Sandpack 模板加载、智能标题、上下文压缩和 AI 生成 runtime 改为按需加载。
- 已拆分 `provider-config`，设置页只加载默认 URL、URL 解析和模型列表 fetch；真正的 AI SDK provider 仅在生成、压缩、智能标题等需要模型时加载。
- 已为 Vite 配置稳定 `manualChunks`，按 React、Radix、Lucide、Markdown、Sandpack、AI SDK、编辑器和工具依赖分组。
- 生产构建不再出现超大 chunk 警告；首屏入口 chunk 从约 1.7MB 降至约 256KB，最大 chunk 为 `vendor-ai` 约 484KB。
- 已通过 `pnpm lint`、`pnpm test`、`pnpm build` 验证。

后续工作：

- 用浏览器 smoke test 覆盖生成入口、智能重命名、设置页模型拉取和代码预览按需加载路径。
- 后续若继续增加大型依赖，需要按功能边界继续放入明确 chunk。

验收标准：

- 首屏不静态加载 Sandpack、AI SDK 生成器和 provider factory。
- `pnpm build` 不再输出 chunk size warning。
- 生成、上下文压缩、智能标题、代码预览仍可按需工作。

### 阶段六：存储治理与清理入口

目标：让用户知道本地数据占用在哪里，并能安全清理历史数据。

阶段进展：

- 已新增 `src/lib/utils/storage-governance.ts`，按会话、消息、项目文件、压缩上下文、快照、记忆、技能和安全审计记录估算本地占用。
- 已在系统设置中增加“存储治理”面板，展示本地数据摘要和清理入口。
- 已支持清理非当前归档会话、删除非当前空会话、按每会话最近 20 个裁剪旧快照、清空技能脚本审计日志。
- 快照裁剪复用 patch 链重建逻辑，确保裁剪后仍可回放剩余历史。
- 已新增 `src/lib/utils/storage-governance.test.ts`，覆盖统计、清理候选和快照裁剪回放。
- 已通过 `pnpm lint`、`pnpm test`、`pnpm build` 验证；本地 dev server HTTP smoke 返回 200。受当前浏览器进程权限限制，Playwright 页面级截图 smoke 未完成。

后续工作：

- 如需更精确的 IndexedDB 占用，可继续读取各 localforage 实例的原始持久化大小。
- 为设置页存储治理交互补浏览器级 smoke test。

验收标准：

- 用户可以看到本地数据占用摘要。
- 用户可以按类别清理数据，且默认不误删当前会话。
- 清理逻辑有测试覆盖。

### 阶段七：外部工具安全护栏

目标：给网络型工具增加统一的资源边界和可观测性。

阶段进展：

- 已新增 `src/lib/tools/network-guard.ts`，统一提供 fetch 超时、并发 map、数量 clamp、数组/对象裁剪、文本截断和安全错误消息。
- 已为网页搜索、网页读取、Jina fallback、图片搜索和 NPM 搜索接入超时、结果数量限制、内容截断和截断元信息。
- `web_reader` 默认最多读取 5 个 URL，Jina fallback 并发限制为 3，页面正文截断为 12k 字符。
- 搜索结果默认限制在 10 条以内，图片结果最多 20 条，NPM 搜索最多 10 条，NPM 详情限制 README 和依赖数量。
- 已在系统设置中增加“安全中心”摘要，集中展示账号模式、凭据金库状态、代理 allowlist 状态、启用技能数量和外部工具状态。
- 已新增 `src/lib/tools/network-guard.test.ts`，覆盖 clamp、数组/对象裁剪、文本截断和并发限制。
- 已通过 `pnpm lint`、`pnpm test`、`pnpm build` 验证。

后续工作：

- 为服务端代理工具返回增加更细的错误分类和重试建议。

验收标准：

- 网络工具不会无限等待或返回过大的上下文。
- 用户能在设置中看到外部能力的安全状态。
- 工具错误更可诊断。

### 阶段八：项目健康检查与自动 QA

目标：让 Open Builder 更像完整的本地 AI 开发工作台。

阶段进展：

- 已新增 `src/lib/tools/project-health.ts`，提供纯逻辑 `runProjectHealthCheck` 和 AI 工具 `project_health_check`。
- 健康检查覆盖空项目、`package.json` 缺失/非法、常见入口文件缺失、`index.html` title/viewport、`.env.example` 未配置项、可访问性基础问题、明显大固定宽度响应式风险和 Sandpack 控制台 error/warn。
- 已在工具工厂注册 `project_health_check`，AI 可在生成后主动调用并读取当前文件与控制台日志。
- 已新增 `/health` slash command，用户可直接触发项目健康检查与修复建议。
- 已新增可配置“自动 QA 回合”系统设置，默认关闭；开启后普通生成成功完成时会自动调用项目健康检查，并让 AI 修复明显的构建/运行错误。
- 自动 QA 具备防递归策略：`/health`、`/review`、`/continue` 等主动检查或继续任务不会再触发额外 QA 回合。
- 已新增 `src/lib/tools/project-health.test.ts`，覆盖健康项目、非法依赖文件、运行时错误、忽略控制台模式、缺失图片 alt、空图标按钮和固定宽度响应式风险。
- 会话导出包已增加可选 `generationLog` 摘要，记录消息数量、工具调用统计、失败工具结果、项目文件数量、快照数量和导出时刻；旧导出包仍可正常导入。
- 已通过 `pnpm lint`、`pnpm test`、`pnpm build` 验证。

后续工作：

- 扩展风格库、技能市场和本地 Git 集成。
- 逐步评估本地 Git 集成、多模型分工和高风险自动审查。

验收标准：

- 用户能看到一次生成的完整质量闭环：计划、实现、检查、修复、交付。
- 高级用户能沉淀自己的模板、技能和风格资产。
